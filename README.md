# 软件版本信息微站 · Version Hub

一个**零依赖、零构建、零后端**的微型网站：管理员在后台录入软件版本信息，客户端只读查看表格并跳转百度网盘下载。数据就是仓库里的一个 JSON 文件，托管在 GitHub Pages 上完全免费。

---

## 一、快速开始（本地，30 秒）

### 方式 1：直接双击（最简单）

双击 **`index.html`** 即可在浏览器中打开。

> 本项目专门做了 `file://` 兼容：数据通过 `data/versions.js` 以 `<script>` 方式加载，
> 不依赖 `fetch`，因此无需任何服务器就能完整运行。

### 方式 2：起本地服务器（推荐，最接近线上效果）

双击 **`start-local.bat`**，会自动检测 Python / Node 并在 <http://127.0.0.1:8080> 启动。

此模式下数据走 `fetch data/versions.json`，与 GitHub Pages 上的行为**完全一致**。

### 登录账号

| 账号 | 密码 | 角色 | 进入页面 |
|---|---|---|---|
| `admin` | `admin` | 管理员 | 后台管理（录入 / 编辑 / 导入导出） |
| `001` | `001` | 客户端用户 | 只读版本表格 + 下载 |

> 登录页下方有「管理员入口 / 客户端入口」两个快捷按钮，点一下自动填充，方便演示。
> 想加账号（如 `002`）：编辑 `config/site.js` 的 `accounts` 数组，照格式加一行。

### 示例数据

仓库自带 2 条示例版本（`v1.2.0` / `v1.1.0`），方便你立刻看到效果。
正式使用前请到后台**删除示例数据**，或直接用「导入 CSV」覆盖。

## 二、后台怎么用

### 录入一条新版本

1. 左侧表单填写：**版本号**、**串口屏版本**、**上传日期时间**（默认当前时刻，精确到秒）、**发布通道**、**下载链接**、**提取码**
2. **README / 版本说明** 支持 Markdown，点「预览」可实时查看渲染效果
   - 以 `- ` 开头的条目会被自动提取为「更新日志」显示在客户端
3. 点 **💾 保存版本**（快捷键 <kbd>Ctrl</kbd>+<kbd>S</kbd>）

贴心细节：

- **版本号自动建议**：打开表单时自动填「最新版末位 +1」（如 `v1.2.0` → `v1.2.1`），也可点「自动 +1」按钮
- **主控固件与串口屏版本分开记录**：「版本号」是主控固件，「串口屏版本」是 DGUS 屏的工程/固件版本，两个页面都会并列显示；没有串口屏的项目可在「⚙ 设置」里关掉这个字段
- **复制为新版本**：列表里点「复制」，以旧版本为模板生成新记录，自动改版本号、时间设为当前、清空内部备注
- **查重**：同一项目内版本号重复会被拦截
- **时间校验**：不允许填写晚于当前时刻的时间（防止把 2026 打成 2999）；老的纯日期数据按「天」比较，今天不会被误判为未来
- **草稿保护**：所有修改实时存入本机浏览器，刷新 / 误关页面都不会丢

### 列表操作

| 按钮 | 作用 |
|---|---|
| 编辑 | 回填表单进行修改，保存后不产生重复记录 |
| 复制 | 以该版本为模板新建（最常用的发版方式） |
| 归档 / 恢复 | 归档后客户端默认隐藏，但数据保留 |
| 删除 | 二次确认；发布前可用「丢弃本机草稿」撤销 |

顶部支持关键词搜索、按通道 / 状态筛选。

### 内部备注

表单最下方的「内部备注」字段**只有管理员能看到**，客户端页面渲染前会剔除该字段。
（admin 账号点「预览客户端」时仍可看到，并标注「仅管理员可见」，方便自查。）

### 导入历史台账

如果已经有一份 Excel 台账：

1. 后台 → **导入 → 下载 CSV 模板**
2. 用 Excel 按模板列填好，另存为 **CSV UTF-8** 格式
3. 后台 → **导入 → 导入 CSV**

导入能力：

- 表头顺序可任意（按列名匹配），缺列自动留空
- 日期时间支持 `2026-11-24 10:30:00` / `2026/11/24 18:05` / `2026-11-24T09:00:00` / `20261124083000` / Excel 序列号（含小数即带时刻）；纯日期 `2026-11-24`、`2026/11/24`、`2026.11.24`、`20261124` 也照旧兼容
- 通道与状态支持中文（`稳定版`）或英文（`stable`）
- 标签用 `;` 分隔，自动拆成数组
- 同项目同版本号 → 覆盖更新，不会产生重复行
- 导入完成后会列出所有处理提示（跳过原因、覆盖记录等）

## 三、发布到网站（关键）

本站是纯静态网站，**数据文件就是数据库**。发布 = 把 `data/versions.json` 与 `data/versions.js` 更新到仓库。有三种方式，推荐第一种。

### 方式 ①：后台一键直推（推荐）

配置一次 Token，之后每次发布只需点一下按钮。

**首次配置（约 2 分钟）**

1. GitHub 右上头像 → **Settings** → 左下 **Developer settings**
2. **Personal access tokens** → **Fine-grained tokens** → **Generate new token**
3. 按下表设置（**权限务必最小化**）：

| 配置项 | 必须设为 |
|---|---|
| Token name | 随意，如 `version-hub-publish` |
| Expiration | 30~90 天 |
| Repository access | **Only select repositories** → 只勾 `version-hub` |
| Permissions | **只给** `Contents` → **Read and write**，其他一律不开 |

4. 生成后复制 Token（`github_pat_` 开头，只显示一次）
5. 回到网站后台 → **⚙ 设置 → GitHub 直推** → 粘贴 → **保存 Token**
6. 会自动「测试连接」，看到 `✓ 连接成功，具备写入权限` 就可以了

**日常发布**

```
后台录入/修改 → 💾 保存版本 → ⬆ 保存到 GitHub → 确认 → 完成
                                              ↓
                        等 1~2 分钟 Pages 重新构建 → 客户端刷新可见
```

一次点击就会在仓库产生一条 commit，同时更新 `versions.json` 和 `versions.js`。

**安全说明**

- Token 只存在**你自己这台浏览器**的 localStorage 里，不写入仓库、不提交 git、不发给任何第三方
- 界面上只显示掩码（`github_pat_AAA…wxyz`），保存后输入框立即清空
- 「⚙ 设置 → 清除」可随时吊销本地保存
- 因为 Token 存在浏览器里，**必须用最小权限的独立 Token**，不要复用你命令行/其他用途的 Token

**技术细节**：走 GitHub **Git Data API** 做原子提交（`ref → commit → tree → commit → 更新 ref`），一次 commit 同时更新两个文件，不会出现「json 更新了、js 没更新」的中间态。更新引用时用 `force: false`，若期间有人往仓库推过东西，GitHub 会直接拒绝并提示你先刷新合并，**不会覆盖别人的改动**。若数据与远端完全一致则自动跳过，不产生空提交。

### 方式 ②：一键脚本（走本地 git）

在本地仓库目录双击 **`发布数据.bat`**：自动从「下载」文件夹找最新的导出文件 → 显示变更摘要 → commit + push。版本数变少时会二次确认，防误删。

### 方式 ③：手动上传（不需要任何 Token）

```
后台 → 导出 → 导出发布文件（JSON + JS）
        ↓  浏览器下载两个文件
   versions.json   versions.js
        ↓
GitHub 仓库 → data 目录 → Add file → Upload files → 拖入两个文件 → Commit changes
        ↓
等待 1~2 分钟 Pages 重新构建 → 客户端刷新即可看到最新数据
```

> ⚠️ 方式 ②③ 都依赖**两个文件一起更新**：
> - `versions.json` —— 线上（GitHub Pages）通过 `fetch` 读取，是**权威数据源**
> - `versions.js` —— 本地双击（`file://`）时读取的**镜像**
>
> 「导出发布文件」会一次生成两个，内容自动一致。方式 ① 由程序保证，无需操心。

### 关于资源版本号（改代码后必看）

三个 HTML 里的 CSS/JS 引用都带了 `?v=2` 后缀，用于**缓存穿透**：

```html
<script src="assets/js/admin.js?v=2"></script>
```

浏览器会缓存静态资源。如果只更新了 JS 而浏览器仍用缓存里的旧 JS，配上新 HTML 就会出错
（例如表头与数据列错位、脚本报错）。加上版本号后，改版本号即等于强制所有访问者重新下载。

**规则**：只要改动了 `assets/` 下的 JS/CSS 或 HTML 结构，就把三个 HTML 里的 `?v=2` 统一改成 `?v=3`、`?v=4`…
只改 `data/` 里的数据文件则**不需要**改版本号（线上数据是 fetch 读取，自带时间戳防缓存）。

### 发布状态怎么看

后台顶栏徽标：

- **已发布状态** —— 本机数据与仓库一致
- **● 有未发布修改** —— 本机有草稿尚未导出上传（浏览器标签页标题也会出现 `●`）

    ├── css/                common / login / admin / client
    └── js/
        ├── utils.js        工具：日期、剪贴板、下载、Toast、主题、版本号比较

### 项目名称与分组展示

**后台**：录入表单第一项就是「项目名称」（必填）。填写相同项目名称的版本会自动归入同一个项目，无需手动建组；输入时会根据已有项目名自动补全，避免「金属浴温控」和「金属浴智能温控系统」这种同物异名导致分组分裂。版本号查重也是**按项目分别计算**的，所以不同项目可以有相同的 `v1.0.0`。

**客户端**：按项目分组展示，结构如下

```
┌─ 烧录工具                            [1 个版本] ─┐
│  📦 生产工具 · 🚀 最新 v0.9.0 · 2026-11-25 08:00:00 │
│  ▸ │ 版本号 │ 串口屏 │ 上传时间 │ 通道 │ 说明 │ 下载 │
│  ▸ │ v0.9.0 │   —   │ 11-25 … │ 实验版 │ … │ ⬇ 🔑 │
└────────────────────────────────────────────────┘

┌─ 金属浴智能温控系统        [2 个版本 · 全部 3 个] ─┐
│  📦 嵌入式固件 · 🚀 最新 v1.2.0 · 2026-11-24 10:30  │
│  ▸ │ v1.2.0 最新 │ DGUS v2.3.1 │ 11-24 … │ 稳定版 │…│
│  ▸ │ v1.1.0      │ DGUS v2.2.0 │ 09-02 … │ 稳定版 │…│
└────────────────────────────────────────────────┘
```

- **项目组按「最近发布时间」排序**，最新有动静的项目排最前
- 组头显示项目名、分类、负责人、最新版本与时间，右侧是版本计数（被筛掉时会显示「· 全部 N 个」）
- 组内每个版本单独一行，点击展开完整 README、更新日志、下载信息与提取码
- 搜索、通道、标签、归档、只看最新等筛选**作用于组内行**；某项目全部版本被筛掉时，整个组自动隐藏
- 项目筛选下拉框只在**项目数 ≥ 2** 时出现，单项目时不干扰视线

在设置里把「启用多项目模式」关掉，可退回单项目形态（隐藏项目字段，客户端只剩一个分组）。**数据结构两种模式完全一致，来回切换无需迁移。**

## 六、数据格式

```json
{
  "meta": { "schemaVersion": 1, "updatedAt": "2026-11-24T10:30:00+08:00", "updatedBy": "admin" },
  "projects": [
    {
      "id": "jinshuyu",
      "name": "金属浴智能温控系统",
      "category": "嵌入式固件",
      "archived": false,
      "releases": [
        {
          "id": "rel_xxx",
          "version": "v1.2.0",
          "screenVersion": "DGUS v2.3.1",
          "date": "2026-11-24T10:30:00",
          "channel": "stable",          // stable | beta | lab
          "status": "normal",           // normal | archived | deprecated
          "tags": ["STM32F407", "FreeRTOS"],
          "readme": "## 本次更新\n- ...",  // Markdown 原文
          "changelog": ["..."],          // 缺省时从 readme 自动派生
          "download": {
            "type": "baidupan",
            "url": "https://pan.baidu.com/s/xxxx",
            "password": "ab12",
            "fileName": "xxx.bin",
            "fileSize": "486 KB",
            "sha256": "",
            "mirror": ""
          },
          "internalNote": "仅管理员可见"
        }
      ]
    }
  ]
}
```

采用 **项目 → 多版本** 两级结构，历史版本自动归组，排序规则为「日期倒序 → 版本号语义化倒序」。

## 七、已知限制（务必阅读）

| 限制 | 说明 |
|---|---|
| **登录是前端软校验** | 账号密码存在于静态文件中，查看网页源码即可绕过。仅用于内部身份区分，**不能保护机密数据** |

| **网盘无法直链下载** | 百度网盘无公开免费直链 API，本站只做「跳转 + 一键复制提取码」 |

需要真正的访问控制？见下方路线图，或参考方案文档中的「方案 C」（Cloudflare Workers / Supabase）。

## 十、视觉风格与浏览器兼容

**设计语言：深空 HUD 科技风**（默认深色，顶栏「☀ 浅色」可切换到浅色主题）

| 元素 | 处理方式 |
|---|---|
| 背景 | HUD 网格（顶部渐隐）+ 四色能量场光晕缓慢漂移 + 水平扫描线纹理 |
| 面板 | 毛玻璃 `backdrop-filter: saturate(170%) blur(18px)` + **HUD 角标**（左上/右下霓虹括号，hover 放大发光） |
| 强调色 | 霓虹青 `#22d3ee` → 蓝 `#3b82f6` → 紫 `#a855f7` 品牌渐变，带辉光投影 |
| 顶栏 | 底部一道循环掠过的青色流光 |
| 数据字段 | 版本号、日期、提取码、统计数字统一等宽字体 + 数字对齐（`tabular-nums`） |
| 徽标 | 大写等宽小标签；「最新」为渐变实心 + 呼吸辉光 |
| 表格 | 表头 sticky 毛玻璃；行 hover 左侧霓虹竖条；展开区顶部渐变淡入 |
| 动效 | 面板入场 `fadeUp` 交错、按钮 hover 扫光、Logo 旋转虚线环 + 脉冲光环、状态呼吸点 |
| 无障碍 | `prefers-reduced-motion` 下关闭全部动画与流光；打印时去玻璃去背景 |

> **中文字距已专门校准**：大写 + 宽字距是为拉丁字母设计的科技风格手法，直接套在中文标签上会散架。
> 因此所有中文标签的字距收敛到 ≤ `.1em`，仅对纯拉丁/数字元素（提取码芯片、密码框、英文副标题）保留宽字距。
> 该约束已写入自动化测试，后续改样式若超标会直接报错。

**浏览器兼容**：Chrome / Edge / Firefox / Safari 近两年版本均可。

- `file://` 打开：全部功能可用（Safari 若禁用本地存储，会自动降级为内存模式并提示）
- 已内置 `Element.closest` 等旧浏览器 polyfill
- `backdrop-filter` 已加 `-webkit-` 前缀；不支持的浏览器会自动退化为半透明纯色面板，不影响可读性
